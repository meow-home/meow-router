# Provider-Management Dashboard UI — Design / Specification

**Date:** 2026-08-29
**Status:** Draft (awaiting user review)
**Parent spec:** `2026-08-29-meow-gateway-v1-design.md` (umbrella v1.0)
**Scope:** Build the renderer dashboard for managing providers, credentials, models, virtual models, the local gateway, and usage/cost. This is the UI vertical slice spanning Phase 1→5 surface, built on the already-implemented backend.

---

## 1. Context & why

The backend (main process) already implements Provider/Account/Model/VirtualModel/Usage repositories, a secure credential service, the provider registry + OpenAI/DeepSeek adapters, and the localhost gateway server. The renderer currently only renders a `ping`/`pong` smoke test (`App.tsx`).

The functional gap is the **user interface** and the **IPC bridge** that exposes backend capabilities to the renderer under the security boundary (credentials never reach the renderer).

This spec delivers a single-page dashboard where the user can:
- Add/remove/enable/disable providers and store their API keys securely.
- Test provider connectivity and discover models.
- Browse models, create/remove virtual models (friendly name → provider model mapping), and pick an active model.
- Start/stop the local gateway and view its status.
- View usage/cost totals.

---

## 2. Chosen approach

**Approach A — Renderer speaks to a narrow typed IPC bridge; main process does all privileged work.**

Confirmed from brainstorming:
- Renderer is presentation-only. It never holds API keys, never calls provider SDKs, never starts servers.
- All provider network calls (`getModels`, `validateCredentials`) and credential read/write happen in the **main process**.
- API keys flow **exactly one way** render→main (`setCredential`), are stored in the OS secure store, and are **never returned** to the renderer. The renderer only sees `hasCredential: boolean` and `testConnection` results.
- No new state/router/form frameworks. Each view fetches its own data on mount through the preload bridge.
- Rejected: Approach B (renderer calls providers directly — violates SECURITY.md + ARCHITECTURE.md) and Approach C (add heavy framework — violates "no framework solely for convenience").

---

## 3. Architecture & process boundaries

```
UI (React, render)
  │ window.meowGateway.* (typed, via preload)
  ▼
Preload (contextBridge, narrow typed API)
  │ ipcRenderer.invoke -> IpcResult<T>
  ▼
Main process IPC handlers ─ validate input ─▶ wrap() → IpcResult<T>
  │
  ├─ ProviderRepository      (provider CRUD, list [no secret])
  ├─ AccountRepository       (credential_ref linking)
  ├─ ModelRepository         (models)
  ├─ VirtualModelRepository  (virtual models)
  ├─ UsageRepository         (dashboard totals, recent)
  ├─ GatewayConfigRepository (host/port/auth/startup)
  ├─ CredentialService       (secure-store read/write; main-only)
  └─ ProviderRegistry        (adapter getModels/validateCredentials)
```

### Security invariants (enforced, not advisory)

1. Renderer NEVER receives an API key. `setCredential` is write-only; `getCredential` is not exposed on `WindowApi`.
2. `discoverModels` calls `adapter.getModels` in main. The renderer receives `ModelInfo[]` only.
3. `testConnection` calls `adapter.validateCredentials` in main. The renderer receives `{ ok, message }` only.
4. Every IPC payload is runtime-validated in the main handler (`isObject`, `isNonEmptyString`, `isValidNewProvider`, etc.) before touching the DB or credential service.
5. Provider IDs, model IDs, and gateways are validated as non-empty strings; enums (provider type) validated against a known set.

## 4. IPC surface (extended)

Extend `src/shared/ipc.ts` (`IPC_CHANNELS` + `WindowApi` + input types). Current channels `ping` + `virtualModel.*` are preserved.

### Providers

| Channel | Input | Return |
|---|---|---|
| `provider.list` | — | `ProviderWithCredential[]` |
| `provider.create` | `NewProviderInput` | `ProviderRow` |
| `provider.update` | `(id, patch)` | `ProviderRow` |
| `provider.delete` | `id` | `boolean` |
| `provider.setCredential` | `(id, secret)` | `void` |
| `provider.testConnection` | `id` | `CredentialCheckResult` |
| `provider.discoverModels` | `id` | `ModelInfo[]` |

`ProviderWithCredential = ProviderRow & { hasCredential: boolean }` — credential presence only, **no secret**.

`NewProviderInput = { type, display_name, base_url? }` (id auto-generated by repo).

### Models

| Channel | Input | Return |
|---|---|---|
| `model.listByProvider` | `providerId` | `ModelRow[]` |
| `model.delete` | `id` | `boolean` |
| `model.setEnabled` | `(id, enabled)` | `ModelRow` |

### Virtual models (existing, unchanged)

`virtualModel.list/get/create/update/delete`.

### Gateway

| Channel | Input | Return |
|---|---|---|
| `gateway.getStatus` | — | `{ running, host, port }` |
| `gateway.start` / `gateway.stop` | — | `{ running, host, port }` |

| Channel | Input | Return |
|---|---|---|

| Channel | Input | Return |
|---|---|---|
| `providerTypes.list` | — | `ProviderTypeDescriptor[]` |

`ProviderTypeDescriptor = { id, displayName, defaultBaseUrl, authType }` sourced from the registered adapters' metadata (OpenAI-Compatible, DeepSeek).

## 5. UI layout — single-page dashboard (dark-first)

App shell: left sidebar navigation; main content area switches views. Keep it lightweight (no router lib requested; a `View` union state in `App.tsx`).

**Sidebar nav items (view id):**
1. Providers
2. Models
3. Virtual Models
4. Gateway
5. Dashboard

### 5.1 Providers view
- List of provider cards: `display_name`, `type` badge, `base_url`, `enabled` toggle, `hasCredential` badge (`✓ key set` / `no key`).
- **Add Provider** button → inline form/panel: type select (from `providerTypes.list`), display name, base URL, API key (password input). On submit:
  1. `provider.create({ type, display_name, base_url })`
  2. `provider.setCredential(id, key)` (if key provided)
  3. optionally `provider.testConnection(id)`
- Per-card actions: **Test**, **Discover models**, **Enable/Disable**, **Delete**.
- Key is never echoed back; after save the card shows `✓ key set`.

### 5.2 Models view
- Provider selector (dropdown of known providers).
- Table of models for selected provider: `display_name`, `provider_model_id`, `context_window`, `input_price`, `output_price`, capabilities, `enabled` toggle, delete.
- **Refresh models** button → `discoverModels(providerId)` then re-fetch list.

### 5.3 Virtual Models view
- CRUD virtual models (map friendly display name → a provider model). Fields: `display_name`, `provider_id`, `provider_model_id`, `routing_policy_id` (nullable), `enabled`.
- List, create, update, delete.

### 5.4 Gateway view
- Status card: `running` (green/red), `host:port`.
- **Start / Stop** buttons.
- Config form: `port`, `auth_enabled`, `startup_enabled`. Save via `gateway.saveConfig`.

### 5.5 Dashboard view
- Stat cards: total requests, total tokens, estimated cost, success / error / aborted counts.
- Breakdown by provider (`byProvider`).
- Recent requests table (limit 50): request_id, virtual model, provider, provider model, tokens, cost, latency, status, error_code, created_at.

## 6. Data flow

**Add provider + key**
```
render: validate form
 → provider.create(input)            (main: repo.create)
 → provider.setCredential(id, key)   (main: credentialService.setCredential)
 → provider.testConnection(id)?      (main: adapter.validateCredentials)
render: refresh list → hasCredential=true
```

**Discover models**
```
render: provider.discoverModels(id)
 → main: credentialService.getCredential (main-only) + base_url
 → adapter.getModels(ctx)             (main-only, no key returned)
 → ModelRepository.upsertByProviderModel(...) for each model
 → return ModelInfo[]
render: refresh Models view
```

**Gateway start/stop**
```
render: gateway.start()/stop()
 → main: gateway.start()/stop()
 → return { running, host, port }
```

**Dashboard**
```
render: usage.dashboardTotals() + usage.listRecent(50)
 → main: UsageRepository.dashboardTotals() + list(50)
 → return totals + rows
```

## 7. Error handling

- Reuse the existing `wrap()` IPC wrapper but generalize it to catch `ProviderError` (from `@meow-gateway/provider-core`), `CredentialError`, and unknown errors, mapping to `{ ok:false, error:{ message, code } }` with a sanitized message (never secret/header material).
- Extend `badRequest()` codes: `INVALID_PROVIDER`, `INVALID_MODEL`, `INVALID_GATEWAY`, `INVALID_CREDENTIAL`, `INVALID_USAGE`, in addition to `INVALID_VIRTUAL_MODEL`.
- Renderer surfaces `error.message` via inline/toast; no raw stack traces. Logging in main stays minimal (no Authorization, no keys, no full prompts/responses).

---

## 8. Validation rules (main, on every IPC input)

- `id`/`providerId`/`providerModelId`: non-empty string.
- `display_name`: non-empty string.
- `type`: one of the known provider-type ids (from registry metadata).
- `base_url`: optional; if present, must be a valid `http(s)` URL **and** pass the SSRF guard (`assertSafeEndpoint`) — reject localhost/private/link-local/metadata targets unless an explicit advanced allow is set.
- `secret`: non-empty string; length capped (e.g. ≤ 8192).
- `port`: integer in `1..65535`.
- `enabled`/`auth_enabled`/`startup_enabled`: boolean.
- `limit`: integer in `1..500`.

## 9. Testing

### Unit (main)
- IPC validation helpers reject malformed inputs (missing ids, bad types, bad URLs, SSRF targets, invalid port).
- `wrap()` maps `ProviderError` / `CredentialError` to safe `IpcResult` without leaking secret material.
- `discoverModels` and `testConnection` correctly exercise the adapter and return sanitized results.

### Unit (render)
- Each view renders correctly against a mocked `window.meowGateway`.
- Add-provider form validates required fields; does not submit invalid data.
- **Security assertion:** no API-key string appears in rendered DOM when `hasCredential` is true; renderer receives no secret channel.

### Integration / security
- `gateway.saveConfig` rejects invalid port/host.
- `provider.setCredential` stores via injected mock credential store; `provider.list` returns `hasCredential` without secret.
- `provider.discoverModels` for an SSRF-forbidden base URL is rejected.
- Gateway start/stop updates status.

Run: `pnpm typecheck`, `pnpm lint`, `pnpm test`.

## 10. Definition of done (this slice)

- Preload `WindowApi` extended and implemented; renderer typing resolves.
- All five views present and functional against real IPC.
- Add/remove/enable/disable provider works; key stored securely; no key in renderer DOM/state.
- Test connectivity + discover models work.
- Virtual model CRUD works (unchanged path).
- Gateway start/stop/config works.
- Dashboard totals + recent requests render.
- Unit + integration tests pass; typecheck + lint pass; no secrets in logs/tests/fixtures.
- Docs updated if contracts changed.

## 11. Non-goals (this slice)

- Adding new provider packages beyond OpenAI-Compatible / DeepSeek (backend supports more later; the picker shows what the registry exposes).
- Editing provider type after creation.
- Advanced routing-policy editor UI (routing_policy_id is selectable by id, policy editor is out of scope).
- Multi-account per provider UI (data model supports it, MVP UI exposes one account).
