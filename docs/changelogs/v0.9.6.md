# Changelog — Meow Gateway v0.9.5 → v0.9.6

## 🐛 Bug Fixes
- **Antigravity: images never reached the model.** A vision request through the
  gateway arrived at Gemini as the literal text `"[object Object]"`: the adapter
  built every message with `String(content)`, so an OpenAI-style content-part
  array (text + `image_url`) lost its image without any error. Image parts are
  now translated to Gemini `inlineData` parts, so Gemini Flash/Pro actually sees
  the picture — the same result Antigravity's own UI gets.
- Remote image URLs are downloaded and inlined (Gemini has no URL image form),
  SSRF-guarded, redirect-free and capped at 10 MiB; a failure now returns a
  readable 400 instead of answering as if no image had been attached.
- **Claude Code / `/v1/messages`: image blocks were dropped.** The Anthropic
  compatibility layer kept only text blocks, so an attached screenshot never
  reached the provider. `image` blocks (base64 or URL, including inside a
  `tool_result`) are now preserved as image parts.
- Images returned by a tool are forwarded as sibling parts of the
  `functionResponse` turn instead of being stringified into the tool result.

## 🧹 Internal & Docs
- Added `FetcherResponse.arrayBuffer()` and `FetcherInit.redirect` to
  `@meow-gateway/oauth-core` so adapters can read binary payloads and refuse
  redirects when fetching client-supplied URLs.
- Documented image input in `docs/API.md` and the Antigravity `inlineData`
  mapping in `docs/PROVIDER_ADAPTERS.md`; added adapter, Anthropic-layer and
  gateway pass-through tests.
- Bumped workspace packages and gateway default version to v0.9.6.
