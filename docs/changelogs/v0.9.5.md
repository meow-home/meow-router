# Changelog — Meow Gateway v0.9.4 → v0.9.5

## 🐛 Bug Fixes
- **Antigravity: every tool round-trip was rejected with 400.** The adapter
  stashed the Gemini `thoughtSignature` inside the tool-call `id` it emitted
  (`call_<n>_ts_<sig>`), but OpenAI-compatible clients (Meow Coding, Claude
  Code, the AI SDK) replace that id with their own. On the second agent turn
  the signature was lost and the Cloud Code Assist API rejected the request
  with `400 INVALID_ARGUMENT` ("Function call is missing a thought_signature in
  functionCall parts"), surfacing as "Antigravity request rejected." on every
  account and model. The adapter now also remembers the signature per
  `(function name + arguments)` in a bounded LRU cache, so it survives a
  client-minted id. The id-stash is kept as the first choice.

## 🧹 Internal & Docs
- Main process now writes provider/gateway diagnostics to
  `<userData>/logs/gateway.log` (best-effort, never throws) so an upstream
  rejection body can be diagnosed after the fact instead of only reaching an
  invisible console.
- Documented the thought-signature round-trip (and the Claude id requirement)
  in `docs/PROVIDER_ADAPTERS.md`; added a diagnostics-logging note to
  `docs/ARCHITECTURE.md`.
