# Changelog — Meow Gateway v0.9.6 → v0.9.7

## 🐛 Bug Fixes
- **Antigravity: a slow provider looked like a permanent hang.** `chat()`
  collected the whole SSE body before yielding, so a client saw nothing until
  the generation had finished. Chunks are now yielded as soon as they are
  parsed; buffering remains only for non-streaming callers
  (`asNonStreamingChunks`).
- **Antigravity: no deadline on the first chunk.** When a model has no upstream
  capacity left, the Cloud Code Assist API accepts the request and then stays
  silent for 30-110s instead of answering `503` (observed on
  `gemini-3.8-flash-tiered` on 2026-11-06). `parseSse()` now applies
  `DEFAULT_FIRST_CHUNK_TIMEOUT_MS` (45s) to the first read only and throws a
  retryable `TIMEOUT`: nothing has been emitted at that point, so the gateway can
  still fail over to the next route, and the client receives an actionable error
  ("Provider sent no data within 45s. The model may be temporarily out of
  capacity.") instead of an indefinite "pending". Override with
  `MEOW_ANTIGRAVITY_FIRST_CHUNK_TIMEOUT_MS`; `0` disables the deadline.
- Deliberate provider errors are no longer rewritten: `parseSse()` rethrows a
  `ProviderError` unchanged instead of mapping every failure to
  `PROVIDER_UNAVAILABLE`.
- `stream complete` now reports `firstChunkMs`, so a queued request is visible in
  the gateway log.

## 🧹 Internal & Docs
- Stopped dumping every translated tool declaration into the gateway log (full
  JSON per tool, ~100 KB per request, which had grown `gateway.log` to 1.4 GB);
  the log now records `toolCount` instead.
- Added adapter tests for incremental yielding (a chunk must reach the caller
  before the provider closes the stream) and for the retryable first-chunk
  `TIMEOUT`.
- Documented streaming pass-through and the first-chunk deadline in
  `docs/PROVIDER_ADAPTERS.md`.
- Bumped workspace packages and gateway default version to v0.9.7.

## ⚠️ Upgrade notes
- Model ids are not touched by this release. `gemini-pro-agent` (upstream
  `404 NOT_FOUND`), `gemini-3.8-flash` (upstream `gemini-3.8-flash-tiered`,
  currently 30-110s to first token) and `claude-opus-4-6-thinking` (upstream
  answers "no longer available, please switch to Claude Opus 5.5") are Google-side
  changes; remap those virtual models in the app to `gemini-3-flash`,
  `gemini-3.5-flash-lite` and `claude-opus-5-5-medium` respectively.
