# Changelog — Meow Gateway v0.1.0

Initial release. A local AI model gateway that manages cloud AI providers and
exposes a local OpenAI-compatible API to coding agents.

## 🚀 New Features

### Electron desktop app
- Scaffold pnpm monorepo with `packages/*` and `apps/*` workspaces.
- Build an Electron + React + TypeScript app shell with sidebar navigation and
  dedicated views (Providers, Models, Virtual Models, Gateway, Usage).
- Add a VSCode Dark+ design system with JetBrains Mono and a shared UI component kit.

### OpenAI-compatible gateway
- Expose a local HTTP server that provides `/v1/chat/completions` with SSE
  streaming end-to-end.
- Provide a provider-core abstraction plus OpenAI-compatible and DeepSeek adapters.
- Proxy requests to the selected provider, with primary/fallback routing and a
  local provider registry.

### Provider & model management
- Add, edit and test provider connections via the UI (OpenAI, OpenRouter, Groq,
  opencode Zen, DeepSeek, generic OpenAI-compatible).
- Discover models from a provider (sync/refresh), preserve enabled state, and
  flag missing upstream models as `stale`.
- Manually add provider-visible and virtual models with full schema validation.
- Add virtual models that expose a stable local name to agents.

### Secure credentials & usage tracking
- Store provider credentials through the OS secure credential store
  (safeStorage) — never plaintext.
- Require a gateway API key by default; generate, mask, copy and regenerate the
  key over IPC, and secure it against the localhost gateway.
- Persist a request log and estimate token usage, latency and cost per request.

### System tray & packaging
- Run on Windows, macOS and Linux with a system tray (show/hide, quit); closing
  the window hides to the tray so the gateway keeps serving.
- Package with branded icons and snake_case artifact names
  (`Meow_gateway_<version>_<arch>.<ext>`).
- Add GitHub Actions CI (typecheck, lint, test, build) and a release pipeline
  that builds installers on a `v*` tag.

## 🐛 Bug Fixes
- Gateway: resolve the provider adapter by provider `type`, not the DB UUID id.
- Gateway: forward assistant `tool_calls` so tool-use history survives upstream.
- Gateway: call an empty bearer token empty, not an unsupported scheme.
- Gateway: read the credential ref that ProviderService writes.
- DB: flush the migration ledger as soon as a migration runs.
- Render: centre button labels and portal modals to the body so overlays cover
  the window.
- Desktop: validate every `createModel`/`updateModel` patch and keep stale
  handling accurate.
